# AI Budget Controls Implementation Plan

**Goal:** Enforce tenant-safe monthly AI spending ceilings with serialized reservations, durable unknown settlement, truthful estimated-cost reporting, and administrator controls that can only tighten deployment limits.

**Architecture:** Migration 0055 stores versioned workspace configuration and one run-linked budget ledger row. Admission takes the existing organization advisory lock, calculates a conservative maximum across all allowed model steps and bounded context/tool results, and reserves that amount before provider invocation. Telemetry settles measured usage atomically with the usage row. Missing telemetry or persistence failures retain the reservation and mark it unknown where possible. Reporting counts measured cost plus outstanding/unknown reservations and exposes the UTC reset boundary and block reason.

**Deployment contract:** `AI_BUDGET_MAX_MONTHLY_USD` is the absolute per-workspace deployment ceiling. If absent, hard spend budgets are unavailable. An administrator may save a lower positive monthly limit, never a higher one. Models without explicit server pricing are rejected while a hard budget applies.

## Task 1: Pricing bounds and persistence

- Add exact known-model price lookup without fallback for hard admission.
- Bound maximum repeated input and output across all allowed steps, including capped tool results.
- Add versioned organization configuration and run-linked reservation/settlement rows in migration 0055.
- Test concurrent admission, rollover, cross-tenant reporting, ceiling enforcement, and retained unknown reservations with real PostgreSQL.

## Task 2: Admission and telemetry settlement

- Reserve inside `beginAgentRun` under the existing organization lock before returning a runnable ID.
- Pass run identity to telemetry and distinguish measured zero from missing usage.
- Atomically record measured usage and settle the ledger; on missing or failed reporting, retain the reservation and persist `UNKNOWN` where possible.
- Never release reservations merely because a run or lease failed.

## Task 3: Reporting and controls

- Expose allowance, measured estimate, held reservations, unknown count, remaining amount, reset time, and current block reason.
- Add administrator-only version-checked budget updates constrained by the deployment ceiling.
- Add an accessible Settings panel and analytics summary, labeling every monetary figure as an estimate rather than provider billing.
