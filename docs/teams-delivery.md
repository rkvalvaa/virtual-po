# Microsoft Teams operations

Teams request-event notifications use the PostgreSQL `teams_deliveries` outbox. Activity creation and matching outbox rows share one database transaction. `/api/cron/teams` leases due work, freezes the Adaptive Card before network I/O, retries explicit HTTP 429 rate limits at most five times, and blocks automatic retry when a timeout, HTTP 408/5xx response, thrown error, or expired post-I/O lease leaves the provider outcome unknown. Provider calls have a ten-second timeout.

Bot commands require `TEAMS_BOT_APP_ID` and `TEAMS_BOT_APP_SECRET`. Ingress accepts at most 256 KiB and verifies the Bot Connector RS256 signature, issuer, app audience, required `nbf`/`exp` lifetime, Teams signing-key endorsement, and exact `serviceUrl`. Signing keys cache for at most 24 hours and refresh once immediately when Microsoft rotates to an unknown key ID. The signed activity tenant ID and stable Teams/AAD user ID resolve through an administrator-created binding to a current VPO membership; display names and payload email addresses are ignored. `vpo create <title>` creates one draft per workspace, tenant, conversation, and provider activity ID. A replay must carry the same command and bound user. `vpo status <request UUID>` reads only the bound workspace. Teams approvals are unsupported and direct users to VPO.

Set `TEAMS_NOTIFICATIONS_VALIDATED=true` and `TEAMS_COMMANDS_VALIDATED=true` separately only after the corresponding deployed, account-backed flow has passed end-to-end validation. Until then, settings and APIs report the capability as unavailable. Routine tests use provider mocks and do not send live Teams messages. This implementation has not performed that deployment-specific validation.

Microsoft's Bot Connector authentication contract requires signature, issuer, audience, lifetime, `serviceUrl`, and applicable channel endorsement validation: [Authenticate requests with the Bot Connector API](https://learn.microsoft.com/en-us/azure/bot-service/rest-api/bot-framework-rest-connector-authentication?view=azure-bot-service-4.0).
