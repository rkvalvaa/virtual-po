# Request archiving

Archive a request from its detail page or select several rows in Requests and choose **Archive selected**. The **Archived requests** view supports searching and restoration. Each bulk result is checked separately; failed items remain selected with an explanation.

Requesters may archive and restore their own drafts. Current reviewers and administrators may manage other requests in their workspace. An active AI run or tracker export must finish before archiving. Archived requests retain their workflow status, content, decisions, comments, attachments, and external links. Restoration returns the request to that same status.

Active searches, review queues, dashboard counts, analytics, similarity suggestions, planning, and AI backlog context omit archived work. Direct history and download links remain available to authorized workspace members. Restore before resuming AI, refinement, review decisions, status changes, or tracker export. Comments and attachment cleanup remain available; attachment deletion retains its existing uploader/administrator checks and explicit confirmation.

Archiving does not delete a tracker issue or any file. There is no permanent request-deletion action or automatic retention policy in this release.
